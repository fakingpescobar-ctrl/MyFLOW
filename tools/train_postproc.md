# Дообучение постпроцессора MyFLOW (Qwen3-0.6B/1.7B + LoRA)

Зачем: у лидера ниши (superwhisper) для этой роли работает **маленькая
специализированная** модель — их `s1-mini` весит 462 МБ, основан на Qwen3 и
дообучен под punctuation / truecasing / text-normalization. Топовость здесь даёт
**специализация**, а не размер.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `tools/build_postproc_dataset.py` | датасет: реальные пары + синтетика с нашим профилем ошибок |
| `tools/train_postproc_lora.py` | LoRA-обучение (маскирование промпта, группировка по длине) |
| `tools/postproc_pipeline.py` | адаптер → слияние → GGUF → квант (одной командой) |
| `tools/eval_postproc.py` | замер через llama.cpp по URL (любая модель) |
| `tools/eval_postproc_hf.py` | замер прямо в transformers (быстрее, без GGUF) |
| `tools/ab_postproc.py` | A/B кандидата против боевой модели на тех же парах |
| `tools/diag_postproc_output.py` | посмотреть, что модель реально выдаёт |

## Уроки, которые дорого дались (не наступать снова)

### 1. Формат входа должен совпадать с обучением буквально

Первая версия стоила 0.618 вместо 0.262 на том же адаптере:

* боевой путь оборачивал вход в `<dictation>...</dictation>`, а обучение шло на
  **голом** тексте;
* шаблон Qwen3 по умолчанию добавляет пустой блок ` thinking`, в бою же стояло
  `enable_thinking=False`.

Теперь: стиль `postproc` шлёт голый текст, обучение идёт с `enable_thinking=False`,
на оба случая есть тесты.

### 2. Профиль синтетики должен повторять реальные ошибки, а не выдуманные

Первая версия портила текст тотально (весь в нижний регистр, вся пунктуация снята,
числа словами). Модель научилась «чинить развалившееся» — и на реальных данных,
где вход **уже оформлен**, не делала ничего (0.262 при сыром ASR 0.267). Теперь
порча тонкая: вставленные филлеры (самая частая правка), повторы, реальные
путаницы слов из истории правок, пунктуация, регистр; тотальная — доля ~8%.

Слова-ошибки берутся **из правок пользователя** (`word_error_pairs`) и только
похожие (`ratio >= 0.6`): «случайное слово вместо случайного» восстановить нельзя,
модель научилась бы гадать.

### 3. Память ограничивает не модель, а логиты

Словарь Qwen3 — 151 936 токенов. Логиты `batch × seq × vocab` в fp32 весят больше
гигабайта на шаг, плюс столько же их градиент. При `batch 8 × seq 512` пик выходил
за 10 ГБ, WDDM уводил в своп, и шаг занимал **14.6 с** вместо 1.2 с.

Рабочие настройки для 10 ГБ: `--batch 4 --accum 4 --max-len 256`
(или `--batch 2 --accum 8 --max-len 384`), `--attn sdpa`,
`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`.

Полезно: тренер **сортирует примеры по длине** и перемешивает окнами по 64 — иначе
один длинный пример в батче заставляет коллатор добить до него все остальные.

### 4. pip в этом окружении зависает

Замирает на середине любой загрузки (процесс жив, CPU 0, соединений 0, файл не
растёт), докачки нет. Лечится `tools/fetch_wheels.py` (PyPI JSON → curl с докачкой
→ `pip install --no-index --find-links`) и `curl -C -` для больших файлов.
Для Python 3.13 доступен `torch 2.6.0+cu124`.
Выбор колеса: `py3-none-any` > `cp313-win_amd64` > `abi3-win_amd64`;
`cp313t` (free-threaded) и `win32` не подходят.

### 5. Конвертер в GGUF: master-ветка не годится

`convert_hf_to_gguf.py` из master стал пакетным (импортирует `conversion`).
Самодостаточна версия тега **b9000** (636 КБ) — её и берёт `postproc_pipeline.py`.

## Порядок работы

```powershell
# 1) датасет (пересобирать после новых диктовок)
.venv\Scripts\python.exe -X utf8 tools\build_postproc_dataset.py

# 2) обучение (учебное окружение, CUDA-torch)
$env:PYTORCH_CUDA_ALLOC_CONF="expandable_segments:True"
.venv-train\Scripts\python.exe tools\train_postproc_lora.py `
    --base data\train\Qwen3-0.6B --max-len 384 --batch 2 --accum 8 --epochs 3 `
    --out data\train\postproc_lora_v2

# 3) быстрый замер качества (без GGUF)
.venv-train\Scripts\python.exe tools\eval_postproc_hf.py --adapter data\train\postproc_lora_v2

# 4) если качество выросло — собрать GGUF и сравнить в бою
.venv\Scripts\python.exe -X utf8 tools\postproc_pipeline.py `
    --adapter data\train\postproc_lora_v2 --name myflow-postproc-qwen3-06b
.venv\Scripts\python.exe -X utf8 tools\ab_postproc.py `
    --model data\train\gguf\myflow-postproc-qwen3-06b-q8_0.gguf --also-all
```

## Цель и текущее состояние (11.10.2026)

Цель: не уступать Qwen3-4B на held-out парах (у 4B среднее **0.220**, точных 60.7 %,
132 мс) при задержке ~50 мс.

Текущий результат: 0.6B после первой версии датасета — 0.262 (55 мс через
llama.cpp), то есть быстро, но пользы нет. Идёт переобучение на перебалансированном
датасете (тонкие правки). Если не хватит — следующий шаг 1.7B (~1 ГБ в Q8).

Ограничения честно: ~444 реальные диктовки — мало для обучения «с нуля», поэтому
основная масса данных синтетика. Она учит чинить именно наш профиль ошибок, а не любые.
