## 1. Вердикт (TL;DR)

Архитектура **здоровая**: слои разделены правильно (recorder → VAD → ASR → LLM → insertion → DB), локальные серверы вместо облака, потокобезопасный оверлей, идемпотентная миграция БД, честные комментарии «почему так». Это не «переписать всё» — это **отремонтировать 7 дефектов, которые сейчас молча съедают речь пользователя**, вернуть к жизни 2 мёртвые фичи и привести в порядок инженерную обвязку.

**Главный вывод:** проект умеет работать, но **не умеет не терять данные**. Четыре независимых пути потери диктовки подтверждены на живом логе и экспериментами:

| # | Что происходит | Доказательство |
|---|---|---|
| 1 | LLM-классификатор интента отвечает `kind:"text"` → фраза **молча исчезает** (нет вставки, нет истории) | эксперимент: `_dispatch_voice_command` возвращает truthy → `_process_recording` делает `return` |
| 2 | Любая ошибка полировки (таймаут/400/битый JSON) → фраза **теряется целиком** | `data/main.log:1960-1992` — 4 трейсбека `RuntimeError: llama-server ответил 400 ... exceeds the available context size` |
| 3 | Авто-обучение словаря **не работает никогда** + 6 секунд 100 % CPU после **каждой** вставки | `learning.py:154` вызывает `clipboard.paste()` без аргумента → `TypeError` → `except: continue` минует `time.sleep` |
| 4 | Исключение в колбэке pynput **навсегда убивает хоткеи** (F7/F8/F9 молча мертвы) | `pynput/_util/__init__.py:232-248`: `self.stop()` при любом исключении в колбэке |

Плюс: `_guard_polish` не спасает короткие фразы — в логе зафиксировано `ASR: «Проверка связи.»` → `LLM: «Провер»` → вставлено `«Провер»` (`data/main.log:1975`).

**Порядок работ:** P0 (потеря речи) → P1 (мёртвые фичи) → P2 (надёжность/латентность) → P3 (инженерия). Подробный план — в разделе 8.

## 2. Что уже сделано хорошо (не ломать при рефакторинге)

- **Разделение слоёв и ответственности** — `audio.py` (захват+VAD), `asr.py`, `polish.py`, `commands.py`, `learning.py`, `db.py`, `insertion.py`, `overlay.py`, `main.py` (оркестрация). Файлы читаются, у каждого есть docstring с «почему так».
- **Аудио**: конверсия Float32→Int16 с асимметричным клампом −32768/+32767 корректна и без переполнения (`audio.py:35-39`); WAV-заголовок `pcm_int16_to_wav` байт-в-байт правильный, без временных файлов (`asr.py:26-38`).
- **VAD**: Silero ONNX-стрим с сохранением hidden-state и контекста 64 сэмпла (`vad.py:23-61`) — это правильная схема, а не энергетический порог; параметры подобраны осмысленно (threshold 0.30, min_speech 180 мс).
- **PTT-автостоп**: срабатывает только если в записи **была речь** и ровно один раз (`audio.py:191-200`) — стартовая тишина не рубит запись. Это неочевидная и верная деталь.
- **Оверлей** (`overlay.py`): Tk в выделенном потоке, обмен только через `Queue` + `after`-поллинг, `show()` не копит очередь при выключенном оверлее, авто-скрытие корректно снимает предыдущий job. Образцовая потокобезопасная схема для Python/Tk.
- **Вставка Ctrl+V**: структура `INPUT` с union `MOUSEINPUT` (40 байт на x64) — известная ловушка SendInput обойдена; проверка `sent != len(events)` на месте; VK-константы не зависят от раскладки (`insertion.py:14-112`).
- **БД**: параметризованные запросы везде (f-string только для имён колонок из dataclass — не инъекция); миграция схемы с сохранением данных (`db.py:82-103`); `with self._conn` = транзакция на операцию.
- **Ошибки/наблюдаемость**: `_tb_to_file` пишет трейсбек **до** консоли (`main.py:54-69`) — верное решение для случая мёртвого stdout; fail-loud на битый `settings.json` (`config.py:119-121`) вместо тихой подстановки дефолтов.
- **`_guard_polish`** (`main.py:495-514`) — правильная идея защиты от LLM-саботажа; один раз реально спас фразу (`data/main.log:2248`: «LLM исказил фразу (41/6 слов) — вставлен сырой ASR»).
- **Изоляция консоли OpenCode**: `FreeConsole/AttachConsole` только в дочернем процессе (`opencode_inject.py:137-182`) — грамотно, ценой обхода реальной проблемы.
- **Приватность**: весь трафик — на 127.0.0.1, телеметрии нет, секретов в файлах нет. Соответствует заявлению README.

## 3. P0 — критические дефекты (теряется речь / ломается процесс)

### P0-1. LLM-интент молча съедает обычную диктовку

**Симптом.** Диктуешь фразу, содержащую слово-маркер («кратко», «удали», «спис…», «стоп», «абзац»), LLM отвечает `kind:"text"` — и **ничего не происходит**: ни вставки, ни записи в историю, ни сообщения об ошибке.

**Причина.** `llm_classify` возвращает `VoiceCommand(kind="text", ...)` (`commands.py:167-171`), `_run_command` не имеет ветки `text` (no-op, `main.py:345-381`), но `_dispatch_voice_command` возвращает этот объект как «команда обработана» (`main.py:343`), а `_process_recording` на truthy-значение делает `return` (`main.py:433-438`).

**Доказательство (эксперимент).** С подменённым `llm_classify`, возвращающим `kind:"text"`:

```
'брат кратко удали этот файл потом'    -> cmd.kind='text' truthy=True pasted=[]
'краткосрочный план на неделю'         -> cmd.kind='text' truthy=True pasted=[]
'список покупок молоко хлеб сыр'       -> cmd.kind='text' truthy=True pasted=[]
```

Дополнительно `is_llm_intent_candidate` ищет маркеры **подстрокой** (`commands.py:116-119`): «краткосрочный», «списке», «удалил» — все считаются командными. То есть под удар попадает заметная доля обычных диктовок, а не экзотика.

**Фикс.**
1. В `main._dispatch_voice_command`: `if cmd is None or cmd.kind == "text": return None`.
2. В `commands.llm_classify` — белый список: неизвестный `kind` → `None`.
3. Маркеры — по границам слов (`\b`), а не подстрокой.
4. Для `summarize/list` из LLM — проверять, что аргумент действительно пересекается с исходным текстом (доля общих токенов ≥ 0.6), иначе считать обычной диктовкой.
5. Инвариант, который стоит закрепить тестом: **ни один путь классификации не может «съесть» текст без явного действия пользователя.**

### P0-2. Ошибка полировки = потеря всей фразы

**Симптом.** LLM не ответила (таймаут, 400, битый JSON, рестарт llama-server) → в буфер не попадает **ничего**, в историю — тоже.

**Причина.** `main.py:444` вызывает `self.polish.polish(...)` без `try`; исключение ловит только общий обработчик воркера (`main.py:292-302`), а `insert_history` идёт уже после (`main.py:462`). Проверка доступности LLM выполняется один раз на старте (`main.py:165-168`): если сервер умер позже — `enabled=True` и каждая диктовка теряется.

**Доказательство (лог эксплуатации).** `data/main.log:1960-1992` — два трейсбека:
```
RuntimeError: llama-server ответил 400: ... request (2056 tokens) exceeds the
available context size (2048 tokens) ... n_prompt_tokens:2056, n_ctx:2048
```
Всего 4 таких отказа (LLM-контекст был `-c 2048`), каждый — потерянная фраза. Сейчас в `start-all.ps1:58` стоит `-c 4096`, но запас по-прежнему тонкий (см. P1-4).

**Фикс.**
```python
try:
    polished = self.polish.polish(asr.text, style=style, dictionary=dic)
except Exception as exc:                      # любая ошибка LLM не теряет речь
    print(f"[myflow] ! полировка недоступна ({exc}) — вставляю сырой ASR")
    polished = PolishResult(text=asr.text, latency_ms=0, skipped=True)
    self._polish_failures += 1                # и запускаем watchdog на возврат
```
Плюс: watchdog раз в 30 с дёргает `/v1/models` и возвращает `enabled=True`, когда сервер поднялся (сейчас это только при старте).

### P0-3. Авто-обучение словаря (Ф9) мертво + 6 секунд 100 % CPU после каждой вставки

**Симптом.** Словарь не учится никогда; сразу после каждой вставки одно ядро загружено на 100 % на 6 секунд.

**Причина.** `watch_pasted_edit` читает буфер как `clipboard.paste()` без аргумента (`learning.py:154`), но **обе** реализации `paste` требуют текст: `ClipboardPaste.paste(self, text)` (`insertion.py:73`) и `OpenCodeInjector.paste(self, text)` (`opencode_inject.py:196`). Возникает `TypeError`, который глушится `except Exception: continue` (`learning.py:155-156`), а `continue` **минует `time.sleep(poll_interval)`** (`learning.py:162`) → холостой цикл до дедлайна.

**Доказательство (эксперимент).**
```
ClipboardPaste.paste signature: (self, text: 'str') -> 'None'
call paste() -> TypeError: ClipboardPaste.paste() missing 1 required positional argument: 'text'
```
Лог: за всю историю эксплуатации `авто-обучение` — **0** срабатываний, `edited_text` пуст во всех 244 записях.

Почему баг не поймали тестом: `test-f9.py:23-29` подставляет `FakeClip` с методом `paste()` **без аргументов** — контракт фейка не совпадает с продакшн-классом. Классический случай «тест проверяет свою же выдумку».

**Фикс.** Ввести честный read-API (`ClipboardPaste.read() -> str`, `check_clipboard` уже есть, но не используется), передавать в watcher читалку, а `continue` заменить на `time.sleep`. Дополнительно: узкие `except` вместо `except Exception`.

### P0-4. Исключение в колбэке хоткея убивает хоткеи навсегда

**Причина.** `_on_press`/`_on_release` вызывают `recorder.start()/stop()` без `try` (`main.py:225, 233-234, 238-243`). Pynput при исключении в колбэке логирует, кладёт `exc_info` в очередь и делает `self.stop()` (`pynput/_util/__init__.py:232-248`) — **слушатель умирает**, приложение превращается в зомби: F7/F8/F9 молча не работают до перезапуска.

**Реальные триггеры (все достижимы):** `audio.py:153` «запись уже идёт» (гонка автостопа и отпускания), `audio.py:132` «не удалось открыть микрофон» (выдернули USB), `audio.py:215` «нет активной записи» (двойной `stop()`).

**Фикс.** Обернуть все вызовы recorder в колбэках; при ошибке — `overlay.show("✗ микрофон")` + запись в лог; добавить супервизор, который перезапускает `keyboard.Listener`, если он умер.

### P0-5. SQLite: `UNIQUE(source_word, app_mask)` не работает для глобальных пар

**Причина.** В SQLite `NULL`-значения в UNIQUE считаются **различными**, поэтому `ON CONFLICT(source_word, app_mask)` никогда не срабатывает при `app_mask IS NULL` (`db.py:64-73`, `db.py:139-150`) → каждый вызов `add_word` для глобального слова создаёт новую строку.

**Доказательство (эксперимент на точной схеме).**
```
global rows after 3x add_word(same, app_mask=None): 3     # должно быть 1
rows after 3x add_word(same, app_mask='code.exe'): 4      # per-app дедуп работает
```

Сейчас в живой БД 1 строка словаря только потому, что обучение мертво (P0-3). Как только обучение починят — словарь начнёт пухнуть дублями, а дубли уходят прямо в промпт (P1-9), съедая контекст.

**Фикс.** Хранить `''` вместо `NULL` + уникальный индекс:
```sql
UPDATE dictionary SET app_mask='' WHERE app_mask IS NULL;
CREATE UNIQUE INDEX ux_dict ON dictionary(source_word, app_mask);
```
(миграция в `_init_schema`, с сохранением текущих данных).

### P0-6. Выбор «системный микрофон по умолчанию» отменяет запуск

**Причина.** `_pick_mic_menu` возвращает `None` и для отмены (Esc), и для пункта `_DEFAULT_SYS` (`pick_mic.py:220-227`), а `pick_mic()` трактует `None` как отмену: `return 3` → `main()` печатает «запуск отменён» и выходит (`main.py:751-753`). `input_device` при этом вообще невозможно сбросить в `None`.

**Фикс.** Раздельные sentinel-значения (например, `_CANCEL = object()`) или возврат `(status, value)`; `None` оставить только как «системный».

### P0-7. PTT: нажатие F8 во время обработки теряется; автостоп + автоповтор рвёт фразу на куски

Два связанных дефекта в одном месте:

- `main.py:223`: `elif not self._ptt_held and not self._busy:` — если воркер занят (обрабатывает предыдущую фразу **или даже live-превью**, см. P2-1), нажатие F8 **молча игнорируется**: нет звука, нет оверлея, нет строки в логе. Начало речи потеряно.
- После VAD-автостопа `_ptt_held` сбрасывается в `False` (`main.py:257`), а клавиша физически ещё удерживается → автоповтор WM_KEYDOWN приходит как повторные `on_press` → при незанятом воркере `_begin_recording()` стартует **новую** запись прямо во время речи. Диктовка режется на куски (а если предыдущий `stop()` ещё не завершился — прилетит `RuntimeError` из `audio.py:153` и сработает P0-4).

**Фикс.** Ввести отдельный флаг «клавиша физически удерживается» (`_key_down`), не сбрасывать его при автостопе и не стартовать запись, пока он поднят; снять блокировку по `_busy` (запись можно начинать всегда, очередь примет), а занятость показывать в оверлее.

## 4. P1 — фичи, которые заявлены, но не работают (или работают не так)

### P1-1. Live-превью умирает после первой фразы (AUTO)
`_prev_interval_samples_in_phrase` инициализируется в `start_continuous` (`audio.py:243`), обновляется в `_on_audio_continuous` (`audio.py:316-321`), но **не сбрасывается** ни в `_emit_utterance` (`audio.py:364-376`), ни в `discard`, ни в `force_finish`. После фразы длиной T первое превью следующей фразы появится только когда её длина превысит `T + 1.8 с`; после длинной фразы — не появится вообще. В PTT аналогичный счётчик корректно сбрасывается (`audio.py:165`) — это явный oversight. **Фикс:** обнулять счётчик на границе фразы.

### P1-2. «Отмена» (F9 и голосовые «стоп/скип») не отменяет
В AUTO F9 делает только `recorder.discard()` текущей фразы (`main.py:211-214`); фраза, уже ушедшая в очередь или обрабатываемая, всё равно будет вставлена. В PTT `_cancel_recording` не чистит очередь. При этом `recording_duration_ms > 0` истинно **всегда** после первой записи (`_total_samples` не сбрасывается в `stop()`, `audio.py:207-222`), поэтому ветка «отменено» отрабатывает и печатает ложный статус. **Фикс:** счётчик поколений (generation/token) — отмена инкрементирует его, воркер отбрасывает элементы со старым токеном и не вставляет результат.

### P1-3. `_guard_polish` не защищает короткие фразы — реальный случай в логе
Условие `if n_raw >= 3 and (...)` (`main.py:508`) отключает защиту для фраз из 1-2 слов — то есть для самых частых коротких диктовок. Лог:
```
1968  [myflow]   ASR : Проверка связи.
1975  [myflow]   LLM : Провер            (style=plain, polish=350 мс)
```
Модель выбросила слово, защита не сработала, в приложение ушло «Провер». Плюс `summarize` вообще исключён из проверки (`main.py:504`), а сравнение только по числу слов пропускает «ответ вместо полировки» той же длины. **Фикс:** убрать порог `>= 3`, сравнивать множества токенов и длину посимвольно, для `summarize` — проверять сохранение чисел/имён.

### P1-4. Промпт + `max_tokens` не влезают в контекст; обрезанный ответ вставляется как целый
- Системный промпт: `STYLE_PROMPTS[style] + NUMBERS_RULE + OMOPHON_RULES` ≈ 6–7 КБ текста, для русского это ~1.5–2 КБ **токенов** на каждой диктовке (`polish.py:178-187`).
- `max_tokens = 512` фиксирован (`config.py:42`); `finish_reason` не проверяется (`polish.py:213`) → ответ, обрезанный на полуслове, вставляется как готовый. В логе видно ровно такой обрыв («…возможно, «с»).
- `-c 4096` при таком промпте оставляет ~2 КБ токенов на вход+выход; длинная диктовка снова упрётся в 400 (что уже случалось на `-c 2048`).

**Фикс:** проверять `finish_reason == "length"`; `max_tokens = min(1024, len(raw)//2 + 96)`; усекать вход по бюджету; увеличить `-c` до 8192 (для 4B-модели это +~16 МБ KV — копейки) и/или сократить промпты (OMOPHON_RULES — самый жирный блок, его стоит кандидатно подрезать).

### P1-5. Голый «отправь» дублирует последнюю вставку
`commands.py:91` ставит `rephrase_last=True` для `send`, а `main.py:363-368` при `rephrase_last` **повторно вставляет текст** и жмёт Enter. Docstring обещает только Enter (`commands.py:9`). Итог: в чат уходит дубль сообщения. **Фикс:** для `send` — только `_press_key("ENTER")`.

### P1-6. Префикс-команды понижают регистр аргумента; `«списком»` нет в safelist
`arg = normalize(text[len(first):]).strip(" :")` (`commands.py:103`) — нормализация (lower + вырезание пунктуации) применяется к **тексту будущей вставки**: «перескажи Про Москву.» → «про москву». Плюс страховка от ложных срабатываний есть только для «список», а не для «списком» (`commands.py:60-62, 97-101`), и тест это закрепляет (`test-commands.py:38-39`). **Фикс:** срезать оригинал (`text[...].lstrip(" :—-")`), добавить «списком» в safelist.

### P1-7. Per-app маска = полный заголовок окна → выученные пары почти не применяются
`learning.py:65-68` пишет в `app_mask` весь заголовок активного окна (обрезанный до 64), а выборка — `? LIKE '%' || app_mask || '%'` (`db.py:169-174`). Заголовок меняется при смене файла/чата/вкладки → маска не совпадает. Ключ кандидата в kv не содержит app (`learning.py:94-99`) → «первое окно залипает» для всех последующих. Плюс `%` и `_` из заголовка работают как LIKE-вайлдкарды. **Фикс:** маска = имя процесса/приложения (например `opencode.exe`, `Telegram`), ключ кандидата `(src, dst, app)`, `ESCAPE` для спецсимволов.

### P1-8. Learning: `autojunk=True` и двойной `hit_count`
- `SequenceMatcher` по умолчанию (`autojunk=True`) на текстах ≥200 токенов объявляет частые слова «мусором» → ложные пары replace/delete → мусор в словаре (`learning.py:34, 60, 128`). **Фикс:** `autojunk=False`.
- `add_word` уже увеличивает `hit_count` через `ON CONFLICT` (`db.py:143-147`), а затем `learning.py:105` вызывает `bump_word` — счётчик растёт вдвойне. **Фикс:** убрать `bump_word` из пайплайна обучения.

### P1-9. Словарь и вход LLM — инъекция в промпт
`target_word` из словаря вклеивается прямо в **system**-промпт (`polish.py:180-187`), а продиктованный текст уходит в user-сообщение без разделителей (`polish.py:195-198`). Диктовка «игнорируй инструкции» для 4B-модели — реальный риск (в логе уже есть случаи, когда модель **отвечала на диктовку** вместо полировки: `data/main.log:1290-1320`). **Фикс:** обернуть вход в `<dictation>…</dictation>` с явной пометкой «внутри данные, не инструкции», санитизировать `\n` в парах словаря, перенести словарь в user-часть.

## 5. P2 — надёжность, латентность, UX

### P2-1. Пайплайн: неограниченная очередь, где превью стоят впереди реальной речи
`queue.Queue()` без `maxsize` (`main.py:143`); live-превью кладутся в **ту же** очередь (`main.py:282-284`), что и готовые фразы, и обрабатываются тем же единственным воркером. Каждое превью — полноценный HTTP-запрос к whisper (`main.py:306-317`). Следствия: (а) если ASR медленнее темпа превью (окно 4 с каждые 1.8 с), очередь растёт, а финальная фраза ждёт в хвосте; (б) `_busy` выставляется и на превью (`main.py:291`), что блокирует старт новой PTT-записи (P0-7).
**Фикс:** отдельный слот для превью с вытеснением устаревших (генерация/`maxsize=1`), приоритет `Recording`, отмена превью при появлении финальной фразы.

### P2-2. Тяжёлая работа внутри аудио-колбэка
ONNX-инференс Silero и конверсия в Int16 выполняются прямо в PortAudio-callback (`audio.py:168-205, 279-338` → `vad.py:49-61`): до 2 `session.run` на 40 мс блок. Рядом на CPU работают whisper-сервер и llama-сервер — вылет за 40 мс даёт underflow, который затем молча проглатывается (см. P2-3). **Фикс:** VAD + конверсия в отдельном потоке через очередь, в колбэке — только копирование буфера.

### P2-3. Молча теряются блоки аудио и не детектируется отвал микрофона
`if status: return` (`audio.py:389-391`) выбрасывает блок целиком при overflow/underflow — дыры в речи без единого следа в логе. В рантайме `_stream.active` не проверяется: при отвале USB-микрофона callback просто перестаёт вызываться, `stop()` отдаёт усечённый буфер как «валидную» запись, AUTO немеет без ошибки в UI. **Фикс:** не выбрасывать блок со статусом (писать в буфер + счётчик), watchdog по времени последнего блока (например, >1 с тишины в callback → событие «микрофон отвалился» + оверлей).

### P2-4. ASR-клиент без ретраев и с одним таймаутом
`asr.py:45-73`: `requests.post` без `Session` (keep-alive), без `Retry`, `timeout=60` — один скаляр и на connect, и на read. Зависший сервер держит единственного воркера 60 с, транзиентный обрыв теряет фразу. `resp.json()` не защищён от не-JSON; `resp.text` зависит от charset-эвристики (риск мойибаке на русском). **Фикс:** `requests.Session` + `HTTPAdapter(max_retries=Retry(...))`, `timeout=(3, 30)`, `json.loads(resp.content.decode("utf-8"))`, обработка 503/busy.

### P2-5. Вставка: буфер обмена, слепые задержки и ложный «✓ вставлено»
- `pyperclip.paste()` возвращает `""` для картинок/файлов (проверено: `paste_windows` возвращает `""`, если нет `CF_UNICODETEXT`), и код восстановит буфер как пустую строку → **скопированные файлы/картинка уничтожаются безвозвратно** (`insertion.py:77-89`).
- Магические `sleep(0.05)` / `sleep(0.15)` без ретраев и без ожидания освобождения буфера (`insertion.py:83, 88`) — в медленных приложениях вставится старый или пустой текст.
- `main.py:484` показывает «✓ вставлено» **до** проверки результата (для clipboard-пути результат вообще не проверяется), при этом SendInput не доходит до окон с более высоким integrity level (UIPI) — пользователь видит ложный успех.
- `delete_last` жмёт Ctrl+Z через pynput `'z'`; на русской раскладке `VkKeyScan('z')` даёт −1 → уходит UNICODE-инъекция → undo не срабатывает, а оверлей рапортует «⎌ отменено» (`main.py:394-408`). **Фикс:** слать VK 0x5A напрямую.
- В Windows Terminal/tmux `Ctrl+V` — не вставка (нужен `Ctrl+Shift+V`), а bracketed paste не используется.

### P2-6. Хоткеи улетают в активное окно
`keyboard.Listener` создан без `suppress` (`main.py:174-177`) → F7/F8/F9 продолжают уходить в приложение (в IDE F8 = «шаг отладки»). **Фикс:** `suppress=True` для наших клавиш (или `win32_event_filter`).

### P2-7. Конфиг без валидации → KeyError пачками
`_load` делает `setattr` любых ключей из JSON без проверки типов (`config.py:112-117`), а словарь `flags` замещается целиком: если в существующем `settings.json` нет нового флага, `flags["overlay"]` бросит `KeyError` (`main.py:169, 440, 476, 485`). В `main()` это не поймано (try только вокруг `app.start()`), в воркере — «ОШИБКА фразы» на каждой фразе. `pick_mic()` и `MyFlowApp()` тоже вне try (`main.py:751, 754-759`) — битый settings.json даёт голый трейсбек вместо русского сообщения. **Фикс:** merge с дефолтами, валидация диапазонов, понятные сообщения, единая точка `load_settings() -> Settings | None`.

### P2-8. Логирование
`_tee_log` пишет в `data/main.log` без ротации и без блокировки из всех потоков, `flush()` без `try` в отличие от `write` (`main.py:706-731`); в файл попадают ANSI-последовательности TUI `pick_mic`. Плюс в логе — **полный текст диктовки** (приватность). **Фикс:** модуль `logging` с `RotatingFileHandler`, таймстемпами, уровнями; ANSI-коды отключить для файла; отдельный «тихий» режим; ретеншен.

### P2-9. Жизненный цикл процесса
Выход только по `KeyboardInterrupt` (`main.py:760-767`): закрытие консоли / logoff / `CTRL_CLOSE_EVENT` убивают процесс без `app.stop()` (очередь теряется). `stop()` не джойнит потоки и не вызывается при исключении в `start()`. Нет мониторинга ASR/LLM после старта. **Фикс:** `try/finally` вокруг mainloop, хендлеры `SetConsoleCtrlHandler`/`signal`, гарантированный `stop()`, периодический health-check.

### P2-10. `pick_mic` (TUI при каждом запуске)
Нет `isatty()` и таймаута: без консоли `msvcrt.getch()` бросит исключение (ловится только `KeyboardInterrupt`, `pick_mic.py:144-162`), с консолью без пользователя — вечное ожидание; нет «оставить текущее». `_probe` использует `sd.rec`+`sd.wait()` без таймаута и порог RMS 1e-4: тихий микрофон помечается мёртвым, шумный — живым (в логе есть прогоны, где **все** устройства помечены ✗). Фильтр по подстрокам «mic/микрофон» прячет USB/BT-устройства с другими именами. **Фикс:** таймауты, возможность отмены, «Enter на текущем», сохранение выбора.

### P2-11. БД и данные
- Нет `PRAGMA journal_mode=WAL` и `busy_timeout`; watcher обучения создаёт **второе** соединение (`main.py:568`) → «database is locked» будет глохнуть молча.
- Нет индексов по `history(created_at, app_window)`, нет ретеншена (244 записи и растёт), нет `VACUUM`.
- На каждую вставку создаётся новый `Database()` и поток, соединение не закрывается (`main.py:566-579`) — утечка хендлов.
- `history`/`dictionary` — открытый текст с полной диктовкой.

### P2-12. Мелочи с реальным эффектом
Оверлей: контраст `#e8e8e8` на фоне `#f0f0f0` практически не виден (`overlay.py:16-18`), позиция хардкодит −90 px и не учитывает рабочую область/мультимонитор (`overlay.py:128-136`). Debounce F7 — 300 мс глобальный, осознанный быстрый цикл проглатывается (`main.py:518-534`). `SetWindowLongW` без `SetWindowPos(SWP_FRAMECHANGED)` — стиль может не примениться. `_matches` не поддерживает модификаторы (`ctrl+alt+d`) — только одиночные клавиши.

## 7. Архитектурные переработки (что менять по-крупному, а не заплатками)

1. **Пайплайн v2.** Явный конвейер: `Capture → Segmenter(VAD) → Queue(priority, bounded) → ASR → Polish → Insert`, с (а) поколениями отмены, (б) приоритетом реальной фразы над превью, (в) пер-этапными таймаутами, (д) единым типом `Utterance` со статусом (`captured/asr_done/polished/inserted/failed`) вместо «or Recording or _LivePreview». Это устраняет P0-7, P1-2, P2-1 одним изменением.
2. **Вставка v2 — не через буфер.** Три стратегии с выбором по приложению: (1) `SendInput` с `KEYEVENTF_UNICODE` (печатать текст напрямую, буфер не трогаем вообще), (2) UIA `ValuePattern`/`TextPattern` (чтение и **проверка** вставки + безопасная замена), (3) clipboard+Ctrl+V как fallback. Плюс: сохранять/восстанавливать буфер только если там был текст, никогда не перезатирать CF_HDROP/CF_BITMAP, верифицировать результат и не показывать «✓ вставлено» без подтверждения.
3. **Спекулятивная вставка** (как у Wispr): вставлять сырой ASR сразу после распознавания, затем точечно заменять на отполированный вариант в тех приложениях, где замена безопасна. Это радикально улучшает **ощущаемую** латентность (сейчас e2e ~0.5-1.5 с, а с учётом превью и полировки в логе встречаются 6.8 с).
4. **Надёжность LLM-слоя.** Fallback на сырой ASR (P0-2), ретрай один раз с усечённым входом, бюджет токенов, `finish_reason`, `top_p`/`repeat_penalty`/`stop`, детектор дегенерации, prompt-caching за счёт стабильного префикса, авто-возврат `enabled` по health-check. Отдельно: разделить промпт на «компактный базовый» и «расширенный» и включать расширенный только когда нужен.
5. **Наблюдаемость.** Перейти с `print` на `logging` (уровни, таймстемпы, ротация), добавить счётчики (`phrases_total/failed`, `asr_ms`, `polish_ms`, `insert_ms`, `preview_dropped`, `device_lost`) и две CLI-команды: `myflow-doctor` (микрофоны, серверы, модели, пути, версии, настройки — с человекочитаемым вердиктом) и `myflow-selftest` (прогон пайплайна на сохранённом wav без микрофона).
