# MyFLOW — локальный голосовой диктант (копия архитектуры Wispr Flow)

Полностью локальный диктант-ассистент по образцу Wispr Flow, но без облака:
**Whisper large-v3-turbo (ASR) + Qwen3-4B-Instruct-2507 Q8 (полировка) на RTX 3080**, всё в SQLite.

> Аудит проекта и план работ: [AUDIT.md](AUDIT.md). Что уже исправлено — в разделе
> «Что починено (аудит 09.10.2026)» ниже.

## Установка (с нуля)

Нужны: **Windows 10/11**, **Python 3.13**, NVIDIA GPU (CUDA 12) для серверов.

```powershell
# 1) окружение
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install --upgrade pip
.venv\Scripts\pip install -r requirements.txt

# 2) бинарники whisper.cpp (CUDA-сборка) — положить в bin\whisper\Release\
#    нужен whisper-server.exe (+ dll-ки CUDA 12)
#    релизы: https://github.com/ggml-org/whisper.cpp/releases

# 3) модели — ВНУТРИ проекта (проект самодостаточен, ~5.7 ГБ всего):
#    models\Qwen3-4B-Instruct-2507-Q8_0.gguf        (LLM-полировка, 4.0 ГБ)
#    models\ggml-large-v3-turbo-q5_0.bin            (whisper-fallback, 547 МБ)
#    models\voiceprint\model.onnx                   (проверка голоса, 32 МБ)
#    models\hf-cache\                               (GigaAM ASR, 215 МБ, качается сам)
#    bin\llama-cpp\llama-server.exe                 (llama.cpp + CUDA-dll, 560 МБ)
#    bin\whisper\Release\whisper-server.exe         (whisper.cpp, 1.1 ГБ)
#    Никаких путей на другие диски: всё рядом с кодом.
#    Вынести на другой диск можно осознанно — переменными окружения (ниже).

# 4) проверка
.venv\Scripts\python -m unittest discover -s tests -t .
```

### Переменные окружения (вместо хардкода путей)

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `MYFLOW_MODELS_DIR` | `<проект>\models` | каталог моделей (`.gguf`, `voiceprint/`, `hf-cache/`) |
| `MYFLOW_LLAMA_DIR` | `<проект>\bin\llama-cpp` | каталог с `llama-server.exe` |
| `MYFLOW_WHISPER_DIR` | `<проект>\bin\whisper` | каталог с `whisper-server.exe` |
| `MYFLOW_WHISPER_MODEL` | `<проект>\models\ggml-large-v3-turbo-q5_0.bin` | модель whisper |
| `HF_HOME` | `<проект>\models\hf-cache` | где искать кэш GigaAM |
| `MYFLOW_VOICEPRINT_MODEL` | `<проект>\models\voiceprint\model.onnx` | модель speaker verification |
| `MYFLOW_SILERO_PATH` | `data\vad_models\silero_v6.onnx` | ONNX-модель Silero VAD |

По умолчанию всё берётся из самого проекта; переменные окружения нужны только
чтобы осознанно вынести модели на другой диск. Каталоги `models/` и `bin/` в git
не попадают (модели весят гигабайты). Самодостаточность проверяется тестом
`tests/test_paths.py`: он падает, если ассет оказался вне проекта или в коде
появился абсолютный путь с буквой диска.

Модель VAD (`data/vad_models/silero_v6.onnx`) лежит в репозитории данных и нужна для работы
(исключена из git — при переносе скопируй `data/vad_models/` вручную).

## Запуск (одно окно)

**`start-myflow.bat`** открывает **один** TUI-пульт: он сам поднимает whisper-server и
llama-server скрытыми процессами (логи в `data\`), показывает экран выбора
(микрофон / режим / куда вставлять), а затем живой пульт диктовки с журналом.
Раньше это были три окна — теперь одно.

```
┌ управление в пульте ─────────────────────────────────────────────┐
│ q — выход (гасит и серверы, которые поднял сам TUI)              │
│ r — вернуться к настройкам    s — перезапустить упавший сервер    │
│ c — очистить журнал           o — вкл/выкл графическую плашку     │
└──────────────────────────────────────────────────────────────────┘
Хоткеи диктовки: F8 — PTT (держишь), F9 — отмена, F7 — стиль.
```

Если серверы уже запущены отдельно — TUI определяет их как «внешние», не поднимает
дубликаты и **не гасит их** при выходе.

**Демо-экраны без запуска серверов:**

```powershell
.venv\Scripts\python -m myflow.tui --demo                  # пульт
.venv\Scripts\python -m myflow.tui --demo --screen settings # экран выбора
```

**Вручную (старый способ, отдельные окна):**

```
powershell -File scripts\start-asr.ps1      # whisper-server :8081
powershell -File scripts\start-llm.ps1      # llama-server   :8082
.venv\Scripts\python -m myflow.main         # консольный main без TUI
# либо всё сразу фоново:  powershell -File scripts\start-all.ps1
```

**Тесты:** `.venv\Scripts\python -m unittest discover -s tests -t .`
(122 теста, без серверов/микрофона/GUI; pytest тоже подойдёт — конфиг в `pyproject.toml`).

**Проба пайплайна с микрофоном:** `.venv\Scripts\python -X utf8 tools\e2e_mic.py 4`
(пишет 4 с → распознаёт, учитывает `asr.input_device` из настроек).

### Настройки (`data/settings.json`)

Ключевые ручки (остальное — в `myflow/config.py`):

| Ключ | Смысл |
|---|---|
| `hotkey.ptt_key` / `cancel_key` / `style_cycle_key` | клавиши PTT/отмены/стиля (`f8`/`f9`/`f7`) |
| `hotkey.suppress` | `true` — не отдавать эти клавиши активному окну (в IDE F8 = шаг отладки) |
| `mode` | `ptt` (по кнопке) или `auto` (слушает постоянно) |

| `silence_pause_seconds` | пауза, завершающая фразу (0.9 с) |
| `history_retention_days` | сколько дней хранить историю (0 = вечно) |
| `flags.live_preview` / `learning` / `overlay` / `auto_insert` | фиче-флаги |
| `polish.top_p` / `repeat_penalty` / `max_tokens` | параметры LLM-полировки |
| `style_by_app` | маска окна/процесса → стиль (например `"code.exe": "terminal"`) |

## Структура

```
myflow/           # ядро (пакет)
  tui.py          # ОДНО окно: серверы + выбор настроек + пульт диктовки
  main.py         # оркестратор: хоткеи, очередь, пайплайн, отмена
  audio.py        # запись 16k mono, PTT/AUTO, автостоп по VAD, превью
  vad.py          # Silero v6 (ONNX, CPU) — стрим с hidden-state
  asr.py          # клиент whisper-server (Session+Retry, WAV в памяти)
  polish.py       # клиент llama-server: стили, правила, защита от инъекций
  commands.py     # голосовые команды: точные/префиксы/LLM-интент
  learning.py     # авто-обучение словаря из правок (diff -> dictionary)
  db.py           # SQLite: history / dictionary / settings_kv (WAL)
  insertion.py    # вставка через буфер + SendInput Ctrl+V
  opencode_inject.py  # инжект в консоль OpenCode (WriteConsoleInputW)
  overlay.py      # статус-плашка v2 (тёмный бейдж, рабочая область, click-through)
  pick_mic.py     # TUI выбора микрофона/режима/цели
  config.py       # настройки (data/settings.json) и фиче-флаги
scripts/          # start-asr / start-llm / start-all (пути от расположения скрипта)
tools/            # ручные инструменты: e2e_mic, smoke_overlay, bench_vad,
                  # validate_silero, record_validation
tests/            # unittest-набор (регрессы на все P0-баги из аудита)
data/             # рантайм: settings.json, myflow.sqlite, логи, модели VAD
```

| Слой | Wispr Flow | MyFLOW | Статус |
|---|---|---|---|
| Запись | AudioWorklet 16k mono, чанк 640 (40мс) | `audio.py`: sounddevice 16k mono, чанк 640, Float32→Int16 (кламп как у них) | ✅ |
| Горячие клавиши | PTT Hold, Esc cancel, шорткаты | `main.py`: глобальный PTT (F8), cancel (F9), стиль (F7) через pynput | ✅ |
| Режимы записи | — | `pick_mic.py` при старте (стрелки ↑/↓, Enter, Esc): микрофон → режим (`ptt` — по кнопке, `auto` — слушает постоянно) | ✅ |
| VAD авто-стоп | — | пауза >0.9с завершает фразу; авто-стоп PTT только при наличии речи; жёсткий лимит 60с и в PTT | ✅ |
| Инкрементальный ASR | streaming → live text | `on_interval`: слайдинг-окно (4с) каждые ~1.8с → драфт-превью «… текст» (не вставляется) | ✅ |
| ASR | gRPC streaming → Baseten «Canto 1.0» | `asr.py` → whisper-server (large-v3-turbo, CUDA) `:8081` | ✅ |
| Полировка | gpt-5-nano / gpt-oss-120b | `polish.py` → llama-server (Qwen3-4B Q8) `:8082`; стили plain/casual/formal/terminal/list/summarize + правило чисел + омофоны | ✅ |
| Instruct (пересказ, команды) | gpt-oss-120b | тот же Qwen3-4B, стиль `summarize` (0.3-0.5с, пересказ 2-3 пр.) | ✅ |
| Голосовые команды | — | `commands.py`: точные фразы/префиксы/LLM-интент (стоп, скип, перескажи, списком, отправь, удали последнее, новый абзац) | ✅ |
| Вставка | C# helper (accessibility) | `insertion.py`: Clipboard + SendInput Ctrl+V (буфер не трогает картинки/файлы) | ✅ |
| БД | flow.sqlite (History/Dictionary/Settings) | `db.py`: SQLite history/dictionary/settings_kv, WAL, миграции | ✅ |
| Словарь | personal dictionary, авто-обучение из правок | `learning.py`: diff правок → learned-слова (порог 2); per-app маска окна; глобальные пары без дублей | ✅ |
| Телеметрия | Sentry/PostHog (облако) | поведение НЕ телеметрируется (локально) | ✅ |

### Взято из схемы Wispr Flow (по разбору их `flow.sqlite`)

| Фича | Как работает у нас |
|---|---|
| **Сниппеты** (у них `Dictionary.isSnippet`) | Таблица `snippets(phrase, replacement)`: произносишь «организуй мысли» — вставляется готовый текст. Проверка идёт ДО голосовых команд и полировки. Управление: `python -m myflow.cli snippets add/list/rm` |
| **Наблюдение за полем через AX** (у них нативный helper + `contentObservationEndReason`) | `myflow/axtext.py` + `myflow/ax_read.ps1`: PowerShell-процесс с .NET UIAutomationClient читает текст поля в фокусе. Правки ловятся **без Ctrl+C**; причина окончания наблюдения пишется в `history.observation_end_reason` (`edited`, `observation_window_elapsed`, `textbox_emptied`, `dictated_text_not_found`, `anchor_mismatch`). Если UIA недоступен — автоматический откат на буфер обмена |
| **`formattingDivergenceScore`** | `myflow/textdiff.py`: расстояние Левенштейна по словам, нормированное в 0..1. Пишется в `history.divergence`, используется в `_guard_polish` (LLM переписала > 50 % слов → сырой ASR) и в статистике |
| **Аудио фраз** (у них `audio`/`opusChunks` в БД) | `myflow/audio_store.py`: Int16 PCM сжатый zlib (или OGG, если есть `soundfile`), последние `audio_keep=50` фраз. Упавшую фразу можно перераспознать: `python -m myflow.cli retry` |
| **Категории приложений + стили** (у них `personalizationAppType` + 4 стиля) | `config.detect_category`: 7 категорий (terminal/code/chat/email/notes/docs/browser) по имени процесса, матч по границам слов; `style_by_category` задаёт стиль. Приоритет: ручной F7 > категория > legacy-маска окна > дефолт |
| **Метрики надёжности** (у них `status`, перцентили задержки) | `history.status` (`ok`/`snippet`/`asr_error`/`polish_error`/`empty_asr`/`retried`), `db.stats()` с p50/p90/p99, долей ошибок и средним divergence. Смотреть: `python -m myflow.cli stats` |

**Диагностика:** `python -m myflow.cli doctor` (пакеты, модель VAD, серверы, БД, аудио, AX) и

### Размер окна и колесо мыши (11.10.2026)

**Окно всегда того же размера — и это ТВОЙ размер.** Пульт открывается в размере
из настроек (`tui.cols` / `tui.rows`) и больше не навязывает его: **растянул окно
мышью — размер запомнится** и в следующий раз откроется таким же. Сменить размер
можно и из панели: строка **«Размер окна»**, `Enter` перебирает пресеты
(100x28 → 120x34 → 132x40 → 150x44). Буфер консоли делается ровно под окно (без
истории прокрутки), поэтому «уехать вверх» окну некуда.

> История: первая версия фиксации размера была слишком упрямой — возвращала окно
> к сохранённым значениям через пару секунд после ручного растягивания, и это
> выглядело как «окно сбивается на стандартные настройки». Теперь размер
> применяется один раз при старте, а ручное изменение принимается и запоминается.

**Колесо мыши листает только журнал.** Включается мышиный режим VT
(`CSI ?1000h` + `CSI ?1006h`): терминал отдаёт колесо приложению, а не
прокручивает собственный буфер. Пульт разбирает SGR-события (`ESC [ < 64;x;y M`)
и листает журнал, **только если курсор над журналом**; события над другими
блоками игнорируются. При выходе мышь возвращается терминалу, иначе колесо
«залипает» в режиме приложения.

| Ключ в `settings.json` → `tui` | Смысл | По умолчанию |
|---|---|---|
| `cols`, `rows` | размер окна (0 = запомнить текущий при запуске) | `0`, `0` |
| `fixed_size` | держать размер неизменным | `true` |
| `mouse_wheel` | колесо листает журнал, окно не прокручивается | `true` |

Мелочи: текст в окне выделяется с **Shift** (обычное поведение приложений с
мышиным режимом); клавиши `PgUp`/`PgDn`/`Home`/`End`/`↑`/`↓` листают журнал
как и раньше; при отключённом `mouse_wheel` колесо снова принадлежит терминалу.

## Режимы распознавания: включить можно только один

«Авто-выбор» и «Судья LLM» — **несовместимые режимы**. Если один включён, второй
**не включится**: пульт откажет и объяснит, что делать. Ничего не переключается
само — режим меняется только твоим явным действием.

```
04:11:17  ! сначала выключи "Авто-выбор" — режимы несовместимы (оба гоняют whisper и LLM)
```

| Режим | Что происходит на фразе | ASR-время |
|---|---|---|
| **ничего не включено** | только GigaAM; whisper-сервер не поднимается, ~1 ГБ VRAM свободен | 56 мс |
| **«Авто-выбор»** | GigaAM первым; при подозрительном результате (обрывок, нет точки, медленный темп) — whisper | 67 мс |
| **«Судья LLM»** | оба движка, локальная LLM склеивает лучший текст; если ответ отбракован предохранителем — внутри применяется правило авто-выбора по уже готовым текстам | ~390 мс |

Порядок действий для смены режима: **сначала выключи текущий** (Enter по его
строке), **потом включи нужный**.

Важные детали:

* отказ виден в журнале как `!` с объяснением, состояние при этом не меняется —
  никаких «тихих» переключений;
* `whisper_needed()` учитывает оба флага: сервер поднимается для любого из
  режимов и **не гасится**, пока режим активен (был баг: выключение авто-выбора
  глушило whisper, нужный судье);
* при отбраковке склейки whisper **не гоняется второй раз** — правило авто-выбора
  применяется к уже полученным текстам (проверено тестом: ровно один вызов);
* если не поднялся сервер или не отвечает LLM — режим не включается, и в журнал
  пишется причина, а не тихое «включено, но не работает».


## LLM-судья: склейка двух распознаваний (11.10.2026)

Режим для максимальной точности: прогоняем **оба** движка и просим локальную LLM
собрать из двух текстов один самый верный. Включается в панели строкой
**«Судья LLM»** (по умолчанию выключен — он втрое дороже по времени).

Замер на 624 реальных фразах (полный пайплайн, WER к «эталонному» тексту, «ё»=«е»):

| Конфигурация | WER p50 | WER среднее | Точных совпадений | ASR-время |
|---|---|---|---|---|
| только GigaAM | 0.083 | 0.138 | 42.1 % | 56 мс |
| только whisper | 0.111 | 0.147 | 36.7 % | 137 мс |
| авто-выбор (второе мнение по признакам) | 0.071 | 0.130 | 44.7 % | 67 мс |
| **судья: склейка двух** | **0.040** | **0.107** | **49.0 %** | ~390 мс |

Что выяснилось в эксперименте (`tools/experiment_llm_judge.py`):

* просить судью **выбрать** A или B — бесполезно: хуже обоих движков (среднее
  WER 0.143 против 0.135 у whisper), совпадение с «оракулом» всего 69 %;
* просить **склеить** — работает: 64 % ответов дословно совпадают с одним из
  входов (судья неявно выбирает лучший), остальные аккуратно правят слова
  («комиты» → «коммиты»);
* у судьи **нет аудио** — он оценивает правдоподобность, поэтому один раз из 624
  выдал эхо промпта («То, что человек реально сказал.»). Отсюда
  **предохранитель**: склейка должна быть близка хотя бы к одному входу и не
  содержать служебных фраз промпта — иначе берётся обычный результат. С
  предохранителем результат даже чуть лучше (среднее 0.114 против 0.116), а
  отбрасывается 0.3 % ответов.

Живая проверка на реальных фразах (GigaAM + whisper + судья): «комиты» →
**«коммиты»**, время 348–1653 мс на фразу — укладывается в 1–2 с после
распознавания.

## Авто-выбор движка: быстро для простых, точно для сложных (11.10.2026)

Замер на 624 реальных диктовках показал, что GigaAM **в 2.4 раза быстрее**, но
whisper **точнее** (в том числе на коротких фразах). Решение — не выбирать один
раз и навсегда, а спрашивать второе мнение только когда результат подозрителен.

Как работает (`myflow/asr_router.py`, включено по умолчанию):

1. GigaAM распознаёт фразу первой — **56 мс**;
2. по тексту и длительности проверяются признаки «подозрительно»:
   * обрывок в конце («...ты по.»);
   * нет конечной пунктуации (e2e-вариант GigaAM её обычно ставит);
   * низкий темп речи (слов/с) — типичный признак пропуска или обрыва;
   * опционально: филлеры (`router_use_fillers`) и очень длинные фразы
     (`router_long_seconds`);
3. если признак сработал и whisper-сервер жив — берём его текст (иначе остаётся
   GigaAM; сбой второго мнения никогда не ломает диктовку).

Результат на тех же 624 фразах (полный наш пайплайн, WER к их тексту, «ё»=«е»):

| Политика | WER p50 | WER среднее | Задержка p50 | p90 |
|---|---|---|---|---|
| только GigaAM | 0.083 | 0.138 | 57 мс | 137 мс |
| только whisper | 0.091 | 0.135 | 137 мс | 241 мс |
| **авто-выбор (по умолчанию)** | **0.071** | **0.130** | **67 мс** | 226 мс |
| Wispr Flow (облако) | — | — | 421 мс | 641 мс |

Второе мнение срабатывает в **20 % фраз** (124 из 624) и именно там качество
заметно выше: WER 0.229 → **0.188**.

Переключается прямо в панели: строка **«Авто-выбор»** (Enter — вкл/выкл, состояние
видно как `[вкл]/[выкл]`). При включении пульт сам поднимает whisper-сервер, при
выключении — гасит его и освобождает ~1 ГБ VRAM. Подсказка строки объясняет, что
это второе мнение.

Те же настройки в `data/settings.json` → `asr`:

* `router` — включить авто-выбор (по умолчанию `true`);
* `router_min_wps` — порог темпа речи (по умолчанию 1.8 слов/с);
* `router_min_seconds` — с какой длины считать темп (1.5 с);
* `router_use_fillers` / `router_long_seconds` — дополнительные признаки
  (режим точности: WER p50 0.083 ценой 126 мс);
* выключить совсем: `router = false` (тогда остаётся только GigaAM; whisper —
  вручную через панель).

Важно: с включённым авто-выбором whisper-сервер поднимается всегда (он нужен как
второе мнение) — это ~1 ГБ VRAM. Освободить: `F11` выгружает LLM, а если нужен
весь VRAM — поставь `router = false` или выбери backend `gigaam`.

## Подтверждение смены движка распознавания

Смена движка — не косметика: whisper требует поднять сервер на `:8081`, и если
это не выйдет, распознавание перестанет работать. Поэтому **Enter на строке «ASR»
в панели больше не переключает молча** — сначала спрашивает:

```
╔═ MyFLOW · пульт-центр ═══════════════════════════════════════════════════════════════════════╗
║              ╔═ Подтверждение ════════════════════════════════════════════════════╗              ║
║              ║               Переключить распознавание на whisper?               ║              ║
║              ║                                                                   ║              ║
║              ║                 Да — Enter / y     Нет — n / Esc                  ║              ║
║              ║  Будет поднят whisper-сервер на :8081; GigaAM останется резервом  ║              ║
║              ╚═══════════════════════════════════════════════════════════════════╝              ║
╚═══════════════════════════════════════════════════════════════════════════════════════════════╝
```

* **Да** — `Enter` / `y`; **Нет** — `n` / `Esc` / `q` (пока окно открыто, остальные
  клавиши панели не действуют, чтобы не нажимать вслепую);
* вопрос разный для каждого направления: при переходе на whisper он предупреждает
  о сервере, при возврате на GigaAM — что whisper-сервер будет выгружен (~1 ГБ VRAM);
* подтверждение можно выключить: `asr.confirm_switch = false` в `data/settings.json`.

## Почему «ASR сломался» и что теперь мешает этому повториться

Реальный случай: в панели нажали **Enter на строке «ASR»** — движок переключился
на whisper и это записалось в настройки, **но whisper-сервер (:8081) не был
поднят** (он стартует только при запуске, если выбран whisper). Итог: все фразы
падали с «whisper-server недоступен», диктовка не работала.

Теперь переключение движка безопасно:

* **в whisper** — сначала поднимаем сервер и дожидаемся готовности; если не
  поднялся (нет `bin\whisper` или модели), переключение **отклоняется**, движок и
  настройка остаются прежними;
* **в GigaAM** — проверяем пакет, греем модель в фоне и **выгружаем
  whisper-сервер** (освобождаем ~1 ГБ VRAM);
* **на живой фразе**: если основной ASR упал (например whisper-сервер умер),
  приложение распознаёт то же аудио через GigaAM, переключается на неё и пишет
  это в журнал — фраза не теряется;
* в панели подсказка к строке ASR теперь говорит, что за чем следует.

Если у тебя когда-нибудь окажется `asr.backend = "whisper"` без сервера —
приложение поднимется на GigaAM само (резерв), а вернуть настройку можно так:

```powershell
.venv\Scripts\python -c "from myflow.config import SettingsStore; s=SettingsStore(); s.get().asr.backend='auto'; s.save()"
```

## Закрытие MyFLOW: ничего не остаётся в памяти и VRAM

Требование: закрыл окно — серверы погасли, память и VRAM свободны (важно перед
игрой). Сделано три уровня защиты:

1. **Обычный выход** (`q` или `Ctrl+C`): TUI останавливает серверы сам
   (`Supervisor.stop_all()` — гасит только те процессы, что запустил он).
2. **Job Object с `KILL_ON_JOB_CLOSE`** (`myflow/jobobj.py`): каждый запущенный
   сервер привязывается к job'у, и если процесс MyFLOW умрёт **любым** способом —
   краш, диспетчер задач, `Stop-Process -Force`, закрытие окна крестиком —
   Windows сама снимет серверы. Проверено вживую: убили родителя силой, llama-server
   умер вместе с ним, VRAM освободилась (было ~6 ГБ занято, стало 0.9).
3. **`start-myflow.bat` + `scripts\stop-servers.ps1`**: до запуска убирает хвосты
   прошлого падения, после выхода TUI добивает оставшееся и печатает, что
   остановлено.

Важно: удаляются **только** процессы из папки проекта (`<проект>\bin\...`).
Чужие сборки llama.cpp (например, твои инструменты из другого каталога) не
затрагиваются — скрипт проверяет путь исполняемого файла и показывает «чужие
экземпляры, не тронуты».

Быстро освободить VRAM, не закрывая MyFLOW:

* выключи LLM в панели (**Enter** на строке «LLM») — сервер не будет поднят
  заново даже автолечением, пока ты сам не включишь;
* либо запусти `powershell -ExecutionPolicy Bypass -File scripts\stop-servers.ps1`
  (учти: пока окно MyFLOW открыто, автолечение поднимет LLM при следующей фразе).

## Автолечение LLM (фраза не теряется и не ждёт)

Было: если `llama-server` не успел подняться или упал, фраза вставлялась сырым
ASR, а неудачная полировка **тормозила диктовку на 4–7 секунд** (на этой машине
соединение с закрытым локальным портом не отвергается, а «висит» до таймаута:
2 с на проверку живости, 4 с на запрос).

Стало — три слоя:

1. **Предпрогрев.** При старте, если LLM не отвечает, приложение поднимает её сразу
   в фоне (холодный старт ~8 с) — пока ты ещё не начал диктовать.
2. **Быстрый отказ + короткое ожидание.** Проверка живости идёт с connect-таймаутом
   0.35 с (было 2 с), результат кэшируется на 3 с. Если LLM заведомо лежит — фраза
   вставляется сырым ASR **мгновенно** (0 мс). Если сервер жив, но запрос оборвался —
   ждём до `polish.wait_on_fail_seconds` (2.5 с) и повторяем полировку той же фразы.
3. **Очередь дополировки.** Фразы, ушедшие сырыми, помечаются `polish_error` и
   дополировываются в фоне, как только LLM оживёт (аудио не нужно — берём
   сохранённый текст ASR). В панели видно `N фраз ждут дополировки`.

Замеры: неудачная полировка **5400 мс → 0 мс**, проверка живости **2060 → 355 мс**,
холодный старт сервера больше не съедает первую фразу.

```powershell
python -m myflow.cli repolish            # дополировать очередь сейчас
python -m myflow.cli repolish --insert   # и вставить последнюю фразу в активное окно
```

**Скорость панели (исправлено 10.10.2026).** Панель тормозила и «не слушала»
клавиши, потому что `control_snapshot()` дергал полное сканирование микрофонов
(проба каждого устройства с записью звука) прямо в цикле отрисовки — **11.6
секунды на кадр**, и кэш не помогал: время записывалось *до* скана, поэтому запись
сразу считалась устаревшей. Теперь:

* список микрофонов для панели берётся **мгновенно** (`fast_mic_list()` без пробы),
  а живость проверяется **в фоне**; пока идёт запись, проба вообще пропускается,
  чтобы не отбирать микрофон у диктовки;
* состояние модулей пересобирается раз в 0.4 с, клавиши читаются каждые 0.05 с —
  управление отзывчивое, опрос серверов не мешает;
* смена микрофона и F5 больше не блокируют панель.

Замер: **11 600 мс → 0.7 мс на кадр** (в симуляции цикла — 78 мс с отрисовкой),
переключение микрофона — 0–1 мс.

**Ещё одна причина «кнопки не работают»:** TUI держал СВОЮ копию настроек,
отдельную от приложения — панель меняла микрофон в приложении, а читала старое
значение из своей копии. Теперь у TUI и приложения одно хранилище настроек, и
строка микрофона однозначно определяется как строка управления (раньше она
считалась «модулем» и нажатие уходило в ошибку «неизвестный модуль: mic»).

Проверено вживую (не только тестами): переключение микрофона 13 → 15 →
системный, реальное открытие/закрытие потока при смене авто ↔ PTT, смена движка
ASR GigaAM ↔ whisper, вставка clipboard ↔ opencode, оверлей вкл/выкл.

## TUI: отрисовка, прокрутка журнала, кнопки

**Почему кадр «разъезжался» (исправлено 10.10.2026).** Ширина кадра считалась
через `shutil.get_terminal_size()`, а на Windows он возвращает размер **буфера
консоли** (`dwSize`), а не видимого окна (`srWindow`). У пользователя буфер был
~230 колонок при окне ~120 — кадр рисовался на 230 символов, терминал переносил
строки, и на экране получалась каша из двух «пультов». Теперь:

* `Console.size()` читает `srWindow` через `GetConsoleScreenBufferInfo` — это
  размер **видимого** окна;
* `Console.draw()` дополнительно жёстко обрезает каждую строку по ширине окна
  (ANSI-безопасно, `fit_width`) и не рисует строки ниже высоты — перенос строк
  физически невозможен, даже если размер почему-то соврёт;
* после кадра чистится хвост экрана (`CSI 0J`), поэтому старые строки не
  остаются висеть.

**Прокрутка журнала.** Раньше журнал показывал только «хвост» — прошлое
посмотреть было нельзя. Теперь в пульте:

| Клавиша | Действие |
|---|---|
| **PgUp / PgDn** | листать журнал на страницу |
| **↑ / ↓** | листать построчно |
| **Home / End** | в самое начало / вернуться к «живому» логу |

Позиция хранится как отступ от конца, поэтому новые строки не сбивают то, что ты
читаешь; сверху журнала видно `↑ прокрутка: N строк назад (End — в конец)`.
В журнале хранятся последние 400 строк, всё дублируется в `data/main.log`.

**Подписи и кнопки.** Внизу каждого экрана — полоска «кнопок» с подписями, а не
голая строка подсказок: главное действие подсвечено инверсией.

```
Пульт:      [PgUp/PgDn] журнал   [End] в конец   [r] настройки   [s] серверы   [c] очистить   ▮q выход▮
Настройки:  [↑↓] выбор   [←→] раздел   [F5] пересканировать   ▮Enter запустить▮   [Esc] выход
```

На узком окне полоска переносится на вторую строку — подписи не обрезаются.

## Куда вставляется текст (и почему он больше не «уезжает»)

Раньше вставка шла в то окно, которое активно **в момент Ctrl+V**: если во время
фразы случайно кликнуть мышью в сторону, текст уходил не в тот чат. Теперь
**цель фиксируется в момент старта диктовки**:

* PTT — окно, активное в момент нажатия F8;
* AUTO — окно, активное в момент начала речи (ищется в истории фокуса: фраза
  начинается сама, а длительность известна, поэтому нужный замер находится);
* перед вставкой фокус **возвращается** в целевое окно
  (`SetForegroundWindow` + `AttachThreadInput`, обход запрета Windows на «кражу»
  фокуса), затем идёт Ctrl+V;
* **фокус не отбирается, пока ты сам работаешь мышью или клавиатурой**: если
  активность была меньше 0.8 с назад (системный `GetLastInputInfo`), вставка
  откладывается и выполняется на естественной паузе — либо сразу, как только ты
  сам вернёшься в целевое окно. Управление мышью не теряется;
* если окно закрылось или фокус вернуть не удалось — вставляем в активное и
  пишем об этом в лог (фраза не теряется).

Проверено вживую на двух окнах: фокус в B (имитация «кликнул в сторону»), мышь
активна → вставка **отложена, фокус не отобран**, поле A пустое; после возврата
в A отложенная фраза доставлена и прочитана из поля A. Ранее проверено и то, что
`focus_window(A)` возвращает фокус, когда пользователь на паузе.

Управление и настройки:

```json
"insert_target": "start",        // "start" — как выше; "focus" — прежнее поведение
"refocus_on_insert": true,       // возвращать фокус перед вставкой
"insert_idle_seconds": 0.8       // сколько секунд тишины считаем «паузой»
```

| Клавиша | Действие |
|---|---|
| **F6** | закрепить текущее окно как постоянную цель (повторное нажатие снимает) |
| **F10** | вставить отложенные фразы немедленно |
| F7 | стиль, F8 | PTT-запись/стоп, F9 | отмена |

**F6** нужен, когда диктуешь в один и тот же чат долго: цель не пересчитывается
по моменту старта, а всегда одна и та же — в пульте видно
`вставляю в: ⚲ <чат>`. Диктовка в диктовке в новое окно: просто переключись
мышью в другой чат **до** начала фразы (или сними закрепление F6).

## Если микрофон не виден или «нет сигнала»

Экран настроек и `python -m myflow.cli mic` показывают **одну строку на физическое
устройство**, живые первыми, с причиной и драйвером:

```
python -m myflow.cli mic           # диагностика: кто жив, кто занят, почему
python -m myflow.cli mic --all     # + устройства, скрытые как «мусор»
python -m myflow.cli mic --set 13  # сохранить микрофон по индексу
```

```
ЖИВ  #1   [MME    ] Микрофон (Ardor Gaming Vox)      жив (rms=0.0021)  <- выбран
ЖИВ  #15  [DS     ] Набор микрофонов (Kinect USB)    тихий вход (rms=0.0006)
мёртв #2   [MME    ] Микрофон (Vault )                нет сигнала (rms=0.000015)
мёртв #40  [WDM    ] Микрофон (Realtek HD Audio)      устройство исчезло (пересканируй)
```

Что здесь важно понимать:

* **Драйвер (API) — часть выбора.** Одна и та же физика видна как MME / DirectSound
  / WASAPI / WDM-KS; список склеивает их в одну строку и показывает тот вариант,
  который реально отдаёт сигнал. Приоритет среди живых вариантов:
  **DirectSound → MME → WASAPI → WDM-KS**. Обоснование — замеры на своём железе
  (Ardor Gaming Vox, родной формат 96 кГц/24 бита):
  * **MME** (legacy) у части USB-микрофонов отдаёт почти цифровую тишину:
    медиана rms **2e-5** против **3.3e-4** у DirectSound — в 16 раз тише, и
    «плавает» между пробами (DictationRecorder с MME мог писать тишину, и фразы
    отсекались как «нет сигнала»);
  * **WASAPI** не открывает 16 кГц ни на одной частоте (ни 48, ни 96, ни 192 кГц) —
    `Invalid sample rate`; поэтому он не выбирается;
  * **WDM-KS** теряет индексы устройств после переподключений (`Invalid device`).
* **Живой уровень прямо в настройках.** Под списком микрофонов — полоска уровня
  выбранного (подсвеченного) устройства и **метка порога 0.010**: стрелками
  переключаешь микрофоны и сразу видишь, какой драйвер даёт сигнал и проходит ли
  голос порог. Если полоска не дотягивается до метки — фразы будут отсекаться
  как тишина.
* **«Не открылся» ≠ «молчит».** Первое обычно значит «устройство занято другим
  приложением» (Discord, OBS, Steam, браузер) или индексы драйвера устарели —
  нажми **F5** для пересканирования. Второе — микрофон выключен/убавлен.
* **«Тихий вход»** — сигнал есть, но очень тихий: подними усиление входа в
  «Звук → Запись → Свойства → Уровень», иначе фразы будут отсекаться как тишина
  (в рантайме порог пика 0.01).

### Что тут было починено (10.10.2026)

* **F5 не работал вообще.** Обработчик был, но `_read_key` знал только стрелки:
  у стрелок префикс `\xe0`, а у функциональных клавиш `\x00`, и обе группы шли
  через одну таблицу `{H,P,K,M}`. F5 — это `\x00`+`?`. Теперь разобраны все
  F1–F12, стрелки, Home/End/Delete и VT-последовательности (`ESC[15~`), которые
  присылает Windows Terminal.
* **Микрофоны с «нестандартным» именем исчезали из списка.** Фильтр требовал
  слова «микрофон»/«mic» в имени устройства. Теперь показывается любой **вход**,
  кроме явного мусора (динамики, виртуальные кабели, Stereo Mixer, мапперы,
  SPDIF, первичный драйвер).
* **Проба «живости» была хрупкой.** Порог RMS 1e-4 при реальных значениях
  0.0001–0.0027 приводил к миганию «жив/мёртв» на одном и том же микрофоне
  (особенно у USB-микрофонов в тихой комнате). Теперь: запись 0.45 с с
  отбрасыванием первых 150 мс (USB/BT «раскачиваются»), повтор при неудаче,
  три уровня — `нет сигнала` (≤3e-5) / `тихий вход` (<1e-3, живой с
  предупреждением) / `жив`.
* **Склейка дублей по драйверам** выбирает живой вариант по приоритету
  DirectSound → MME → WASAPI → WDM-KS и показывает его API (раньше при мёртвом
  MME-варианте вся физика считалась мёртвой, а «живой» MME мог писать тишину).
* **Живой индикатор уровня** в настройках (полоска + метка порога 0.010):
  видно, какой драйвер даёт сигнал и проходит ли голос порог. Колбэк индикатора
  сначала падал с `NameError` (в модуле не был импортирован numpy) и показывал
  нулевой уровень — теперь это покрыто тестом.

### ASR: GigaAM v3 вместо/рядом с whisper

`asr.backend` выбирает движок: `gigaam` | `whisper` | `auto` (по умолчанию —
gigaam, если установлен `onnx-asr`). **GigaAM v3 e2e** от Sber — ru-only модель
(ONNX, int8, 215 МБ) и она **работает на CPU**, освобождая GPU под LLM.

> **ОБНОВЛЕНО 11.10.2026.** Первый A/B ниже сделан на 17 записях и сравнивал в
> основном скорость. Прогон **обоих движков по 624 реальным диктовкам** (импорт из
> базы Wispr, `data/eval_wispr/ab_asr.json`) показал обратную картину по ТОЧНОСТИ:
> whisper WER p50 **0.091** / среднее 0.135 / точных 43.3 %, GigaAM — 0.100 / 0.152 /
> 39.1 %, причём whisper лучше во всех диапазонах длины. GigaAM при этом в 2.4 раза
> быстрее (56 против 137 мс) и в 8 раз меньше. Типовые ошибки GigaAM на реальной
> речи: обрыв длинной фразы, термины («комиты» вместо «коммит и пуш»), дописанные
> филлеры. Поэтому whisper из сборки **не удалён**.

A/B на 17 своих записях (`tools/eval_asr.py`):

| | whisper large-v3-turbo | **GigaAM v3 e2e ctc** |
|---|---|---|
| p50 (17 файлов) | 137 мс | **92 мс** |
| средний RTF | 0.022 | **0.013** |
| WER (val_dictation) | 0.29–0.38 | **0.14** |
| Пунктуация и заглавные | нет | **да** (вариант e2e) |
| Галлюцинации на тишине/шуме | «Продолжение следует…» | **пусто** (правильно) |
| Начало длинной фразы | теряет | **сохраняет** |
| Где считается | GPU (~1 ГБ VRAM) | **CPU** |

Живое сравнение на одной записи (30 с):
```

gigaam  : 'Ну что? Теперь ваша очередь Так, и чё? А где живой индикатор? Нихуя не понимаю. Что за ебоата, блядь? Ёбаный рот.'
```

Установка (опционально, ~215 МБ модель скачается при первом запуске):

Модель грузится один раз: при прогретом кэше 0.9 с, при первом скачивании ~24 с —

Нюанс: GigaAM иногда пишет русские слова латиницей («Стоп» → «Stop.»), поэтому в
точные команды добавлены `stop`/`skip` — иначе команда не сработала бы.

### Проверка голоса: диктуете только вы

VAD отличает речь от тишины, но **не отличает вашу речь от чужой** — в комнате с
телевизором или коллегами он честно «слышит речь» и делает фразы из чужого
голоса. Энергетикой это не решается (замер: тихая речь 0.019 против фона 0.026 —
диапазоны пересекаются). Решено нейросетью: **WeSpeaker ResNet34 (VoxCeleb)**
в ONNX, 25 МБ, `onnxruntime`, CPU, ~10–20 мс на фразу.

Модель принимает 80-мерный kaldi-fbank (25/10 мс, hamming) и отдаёт эмбеддинг
голоса (256). Сравниваем косинусом с профилем владельца. Критичная деталь —
**CMN** (вычитание среднего по кадрам): без неё разделение плохое (свой 0.74–0.91
против чужого 0.55–0.70), с ней — чистое:

| Что проверяли | cosine |
|---|---|
| Своя речь (несколько записей) | **0.56 … 0.83** |
| Своя речь, тихая запись | 0.36 |
| ТВ-диктор (чужая речь) | **0.011 … 0.090** |
| Кеннеди (`jfk.wav`, другой язык) | 0.025 |

Порог по умолчанию **0.25** (запас 2.2× снизу и 2.8× сверху).

Управление:
```powershell
python -m myflow.cli voice status                  # состояние профиля и модели
python -m myflow.cli voice enroll <wav> [<wav>…]   # добавить свои фразы (16кГц моно)
python -m myflow.cli voice enroll --from-history 20 # взять свои записи из истории
python -m myflow.cli voice test <wav> [<wav>…]     # проверить: свой голос или чужой
python -m myflow.cli voice reset                   # удалить профиль
```
Профиль — центроид эмбеддингов в `data/voiceprint.npz` (биометрический шаблон,
никуда не отправляется). Он **сам пополняется** вашими удачными фразами (только
уверенно «своими», score ≥ 0.45), поэтому со временем становится устойчивее к
смене микрофона и комнаты. Фразы короче 0.8 с не проверяются: эмбеддинг по ним
ненадёжен, а терять короткую диктовку нельзя.

Чужая фраза **отбрасывается до распознавания**: в истории появляется строка
`status = "other_speaker"`, вставки нет, ASR и LLM не вызываются (замер: 15–66 мс
на отказ вместо полного цикла).

Где проверяем — `voiceprint.mode`:
* **`auto`** (по умолчанию) — только в AUTO-режиме, где микрофон слушает
  постоянно и чужую речь надо отсекать;
* `always` — и в PTT тоже;
* `off` — выключено (то же, что `voiceprint.enabled = false`).

В PTT по умолчанию **не** проверяем: удержание F8 — явное намерение пользователя,
и лишний отказ там вреднее пропуска.

Установка:
```powershell
.venv\Scripts\pip install kaldi_native_fbank
# модель (32 МБ) кладём в models\voiceprint\model.onnx (в проекте):
#   https://huggingface.co/onnx-community/wespeaker-voxceleb-resnet34-LM
#   файл onnx/model.onnx
```

### Whisper-сервер больше не нужен (если ASR на GigaAM)

GigaAM работает как локальная ONNX-модель на CPU, поэтому `whisper-server` на
:8081 не поднимается вообще: `myflow.tui` и `scripts/start-all.ps1` проверяют
`asr.backend` и пропускают его, освобождая ~1 ГБ VRAM. Вернуть можно флагом
`MYFLOW_KEEP_WHISPER=1` или `asr.backend = "whisper"`.

### Что НЕ стоит делать (проверено, а не «на вкус»)

### VAD: параметры рантайма (не «на глаз»)

Прошлый бенч (`tools/validate_silero.py`) гонял `min_speech=480 мс` и паузу
`640/1280 мс`, тогда как в бою — **180 мс речи и 900 мс паузы**. Из-за этого он
«проходил» на артефакте: пауза 1280 мс склеивала две разные фразы в одну
(`val_dict_1` = «Привет. Как дела?» + «Нужно купить хлеб и масло.» — проверено
нарезкой и распознаванием сегментов). Новый `tools/bench_vad_runtime.py` считает
ровно в режиме рантайма и по честным критериям: нет ложных на не-речи + файлы с
речью дают хотя бы фразу + цена CPU.

```
модель               dict      cmd    noise      tv0       tv   A    B    C: мс/с аудио
silero                1-2      1-1      0-0      1-1      1-2   OK   OK      2.6
firered               1-2      1-1      0-0      1-1      1-2   OK   OK      2.9
firered_stream        1-2      1-1      3-3      2-2      1-2   ЛОЖН OK      3.3
ten                   1-2      0-1      5-5      1-1      1-1   ЛОЖН ПОТЕРЯ    3.6
```
Silero стабилен при порогах 0.25–0.35 и любой паузе 450–900 мс (15/15) — текущий
0.30 выбран удачно. **Оставляем Silero** (уже в проде, самый дешёвый).

Остаётся одна известная слабость: фон телевизора на низкой громкости (пик 0.026
против 0.317 у голоса) проходит амплитудный гейт 0.01, и в AUTO-режиме это может
разбудить запись. Лечится адаптивным порогом (пик > 4× недавнего шумового пола) —
не сделано, это отдельная задача с живой настройкой.

### Быстрый путь: без LLM, когда текст уже оформлен

GigaAM e2e отдаёт текст с пунктуацией и заглавными, поэтому LLM часто меняет в
нём почти ничего — а стоит 110–180 мс, то есть **дороже распознавания**.
`myflow/fastpath.py` решает, нужна ли полировка: текст идёт без LLM, если он уже
оформлен (есть конечная пунктуация и заглавная), в нём нет слов-паразитов, нет
чисел словами («восемь тысяч восемьдесят один» правило чисел превратило бы в
8081) и нет дефектов пунктуации вроде «телевизоре..».

Правило работает только для бэкенда GigaAM e2e и стиля `plain` (у тебя это
**217 из 259 фраз, 84 %**); для `terminal` полировка реально переформатирует текст.

Замер на реальных записях: быстрый путь подошёл **8 файлам из 17**, и во всех
восьми LLM изменила бы результат на divergence ≤ 0.05 (то есть терять нечего);
остальные честно ушли в LLM (короткие команды, «числа словами», нет пунктуации,
двойная точка). Сквозной результат в приложении:

| | e2e |
|---|---|
| Быстрый путь (8 фраз) | **p50 104 мс** |
| Через LLM (1 фраза: числа словами) | 982 мс |

В истории такие фразы помечены `status = "fast_path"` (видно в `cli stats`),
выключается флагом `polish.skip_wellformed = false`.

### Адаптивный порог по фоновому шуму — реализован, но **по умолчанию выключен**

Гипотеза была: телевизор на фоне (пик 0.026 при голосе 0.317) проходит
амплитудный гейт 0.01 и в AUTO-режиме рождает «фразу» из чужой речи. Сделал
`audio.noise_gate()`: уровень не-речевых чанков оценивается, фраза должна быть
громче фона в `noise_ratio` раз, но не выше потолка `noise_max_gate`.

Проверка на реальных записях показала, что **пользы нет, а вред есть**:
* в живом цикле recorder хвост телевизора и так не превращается в фразу —
  с гейтом и без него на `val_tv_1` получается 1 фраза (0 отсевов). «Вторая
  фраза» была артефактом офлайн-сегментатора, а не реального пайплайна;
* зато гейт **отбросил настоящую тихую фразу** (`val_cmd_2`: пик 0.019 при фоне
  0.087). Энергия в принципе не различает «тихая речь» и «громкий фон» — их
  диапазоны пересекаются (ТВ 0.026 против речи 0.019).

Поэтому `adaptive_noise_gate = false` по умолчанию: включай `true` только если
диктуешь там, где фон громкий и **долгий** (постоянно говорящий телевизор) —
тогда риск оправдан. В PTT-режиме гейт не применяется вообще (там границы фразы
задаёт сама клавиша F8).

### Что дал тюнинг серверов

| | Было | Стало |
|---|---|---|
| llama-server слои на GPU | `-ngl 35` (последний слой + выходная проекция 389 МБ на CPU) | **`-ngl 99`** — все 36 слоёв |
| Слоты | 4 слота впустую (KV делится, кэш прыгает) | **`-np 1 -kvu`** — один слот, контекст целиком нашему запросу |
| KV-кэш | f16, ~2.4 ГБ | **`-ctk/-ctv q8_0`**, ~1.2 ГБ |
| Генерация | **80 tok/s** | **105–115 tok/s** |
| Полировка (живые фразы) | 260–330 мс | **p50 205 мс / p90 259 мс** |
| VRAM (llama+whisper) | ~7.5 ГБ | **7.3 ГБ** |
| whisper | `-l auto -t 8` | **`-l ru -bs 5 -sns -t 4`** |
| ASR (8–30 с аудио) | RTF 0.015–0.03, ошибки на именах | RTF 0.011–0.021, «меня зовут Максим», «Сухом Логу» |
| e2e (диктовка → вставка) | ~1.2–1.5 с | **719–750 мс** |

Почему `-l ru`: авто-детект даёт лишний проход и иногда промахивается — в логе
был случай, когда русская фраза распозналась как французская (`pour terminer.`),
а `eval_polish.py` показал ещё пачку таких галлюцинаций на тишине
(`Thank you.`, `Sous-titrage Société Radio-Canada`). С `-l ru -sns` они уходят.
Если диктуешь на нескольких языках — поставь `asr.language: "auto"` в настройках.

**Словарь → подсказка whisper** (`asr.prompt_from_dictionary`): термины из словаря
(«Сухой Лог», «Qwen», «opencode») подмешиваются в `initial_prompt` раз в минуту —
имена и доменные слова распознаются заметно лучше, задержки это не стоит.

## Ограничения / честно

- **Пак моделей:** единственный годный — **Qwen3-4B-Instruct-2507 Q8** (полировка 0.3-0.9с,
  пересказ 0.3-1.3с, числа верны с NUMBERS_RULE). Забракованы: Qwen3.5-9B UD/Coder и
  Nemotron-3-Nano-4B (thinking-режим: пустой content при пересказе), gemma-3n-E4B
  (копирует/самоповторяется). Nemotron неплох для полировки (0.5с) — резерв.
- `-c 8192` у llama-server: системный промпт (~1.5-2к токенов) + диктовка + ответ должны
  влезать в контекст (на `-c 2048` в логе были реальные 400 `exceed_context_size`).
- 10 ГБ VRAM = одновременно 1 LLM + whisper (две LLM не влезают, оффлоад убивает скорость).
- **Авто-обучение** ловит правки только если они скопированы в буфер (выделение + Ctrl+C)
  в окне 6 с после вставки; правки мышью без копирования не видны. Правки в разных окнах
  не складываются (порог 2 — в рамках одного окна).
- **Голосовые команды:** «отправь X» с аргументом намеренно НЕ перехватывается; команды с
  аргументом могут сработать, если ты реально диктуешь о пересказе списком. «удали последнее»
  работает через Ctrl+Z не дольше 60 с после вставки. Переоформление последней фразы без
  аргумента вставляется НИЖЕ оригинала (замена выделения небезопасна).
- **Live-превью** не ускоряет финальную вставку (полная транскрипция — при отпускании
  кнопки/паузе), это живой отклик во время длинных диктовок.
- **Вставка через буфер** может конфликтовать с чужой вставкой; restore-логика есть и
  не трогает нетекстовые форматы (картинки/файлы).
- **pynput-хоткеи** требуют прав; при фокусе на elevated-окне Windows (UIPI) хук/вставка
  могут не сработать — статус в оверлее в этом случае не гарантирован.
- Логи (`data/main.log`) содержат распознанный текст — не выкладывай их; каталог `data/`
  исключён из git.
- Ограничения инструментов: `tools/bench_vad.py` тянет `jfk.wav` из интернета при отсутствии
  файла и гоняет другие параметры VAD, чем рантайм (сравнительный бенч, не эталон).
